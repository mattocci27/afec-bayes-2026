Negative density dependence (NDD)

“…rare species suffered more from the presence of conspecific neighbors than common species did, suggesting that conspecific density dependence shapes species abundances in diverse communities.”

- Comita et al. 2010 -

NDD can maintain diversity in communities by preventing common species from dominating the community.

Where we are going: by Day 3, we can ask this kind of question of our own data.

Comita et al. 2010 Science

  • motivation only: no model details today
  • most questions in community ecology have this shape: individuals within species (or sites, or years)

Multilevel model (verbal model: NDD example)

Example inspired by Comita et al. 2010 Science and Song & Katabuchi et al. 2024 Ecology. Density and abundance are scaled (mean = 0, sd = 1).

H: Rare species tend to be rare because they suffer stronger conspecific NDD than common species.

  • Survival rates p ~ conspecific density x (individual-level, logistic regression).
  • Slopes a ~ species abundance (species-level).

Rare species have few seedlings. We want the slope of every species and the pattern among species in one model: a hierarchical (multilevel) model. This is where the course ends.

Likelihood

Likelihood and probability density distribution

\(f(x \mid \mu, \sigma) = \frac{1}{\sqrt{2\pi\sigma^2}}\mathrm{exp} \bigl[{-\frac{1}{2}\bigl\{\frac{x-\mu}{\sigma}}\bigr\}^2\bigr]\)

  • P(data | parameters): Probability of observing the data given the parameters.

  • e.g., when your model is \(x_i \sim \mathcal{N}(\mu = 0, \sigma = 1)\) (normal distribution with mean 0 and standard deviation 1), what is the probability density at x = 1.96?

dnorm(1.96, mean = 0, sd = 1)
  [1] 0.05844094
  • A statistical model always has this form: a distribution for the data (normal, binomial, Poisson, …) with unknown parameters.
  • likelihood is all about probability density (mass) function (normal, log-normal, poisson, beta, gamma, binomial, negative-binomial…)
  • NOTE: throughout the course N(mu, sigma) is written with the standard deviation, as in Stan and in dnorm()

Likelihood of several observations

When your data is x = {-1.5, 0, 1.5} and your model is \(x \sim \mathcal{N}(\mu, 1)\), how probable is the data for a given \(\mu\)?

  • \(L(\mu) = P(-1.5 \mid \mu, 1) \times P(0 \mid \mu, 1) \times P(1.5 \mid \mu, 1)\)
  • \(\mathrm{ln}\;L(\mu) = \mathrm{ln}\;P(-1.5 \mid \mu, 1) + \mathrm{ln}\;P(0 \mid \mu, 1) + \mathrm{ln}\;P(1.5 \mid \mu, 1)\)

The data are fixed. The likelihood is a function of the parameter.

Maximum Likelihood Estimation (MLE)

  • 2 survivors out of 5 seedlings: What is the survival probability of seedlings?

  • \(p\): survival rates, \(1-p\): mortality rate

  • \(L = {}_5C_2 p^2(1-p)^3\) (Binomial distribution)

  • \(\mathrm{ln}\;L = \mathrm{ln}\;{}_5C_2 + 2\mathrm{ln}\;p + 3\mathrm{ln}(1-p)\)

  • \(\frac{d}{dp}\mathrm{ln}\;L = \frac{2}{p} - \frac{3}{1-p} = 0\)

  • Solve: \(p = \frac{2}{5}\)

What the MLE does not tell us

  • Both data sets give the same MLE: \(\hat{p} = 0.4\).
  • With 2 of 5, values such as \(p = 0.2\) or \(p = 0.7\) are still very compatible with the data.
  • A single number hides this uncertainty.
  • What we really want: how plausible is each value of \(p\), given the data? \[P(p \mid \text{data})\]
  • the likelihood is P(data | p), not P(p | data)
  • to turn it around we need Bayes’ theorem

Conditional Probability and Bayes’ Theorem

Conditional Probability

Probability of A occurring given B has already occurred:

\[ P(A \mid B) = \frac{P(A \cap B)}{P(B)} \]

e.g.,

  • P(hangover) = 4%
  • P(baijiu) = 1.5%
  • P(hangover | baijiu) = 85%.
  • probability A occurs given B
  • vertical bar = given
  • at least 1 day for each month
  • the next day after I had beer
  • the next day after I had baijiu

Bayes’ Theorem

\[ P(B \mid A) = \frac{P(A \cap B)}{P(A)} \]

\[ P(A \mid B) = \frac{P(A \cap B)}{P(B)} \]

\[ P(A \mid B) \times P(B) = P(B \mid A) \times P(A) \]

\[ P(A \mid B) = \frac{P(B \mid A) \times P(A)}{P(B)} \]

Why is this useful?

Forward and Inverse Problems: PCR and disease example

  • \(P(\text{Positive})\): 2%, \(P(\text{Infected})\): 0.05%

➡️Forward problem: If you are infected, what is the probability that PCR test is positive?


\(P(\text{Positive} \mid \text{Infected})\): 95%


This is what the lab test is designed to estimate — how likely we are to observe a positive signal given the known infection status (e.g., 95 out of 100 infected samples test positive).

Forward and Inverse Problems: PCR and disease example

  • \(P(\text{Positive})\): 2%, \(P(\text{Infected})\): 0.05%

🔁Inverse problem (Bayesian): If the PCR test is positive, what is the probability that you are infected?


  • \(P(\text{Infected} \mid \text{Positive}) = \frac{P(\text{Positive} \mid \text{Infected}) \cdot P(\text{Infected})}{P(\text{Positive})} \approx 2.4\%\)


This isn’t intuitive, but it’s the probability we actually care about — how likely someone is to be infected, given a positive test result.

  • ask the room to guess before revealing 2.4%
  • 0.95 * 0.0005 / 0.02 = 0.02375

Bayes’ theorem

\[ \textcolor{#d95f02}{ P(\mathrm{Parameter} \mid \mathrm{Data}) } = \frac{ \textcolor{#1b9e77} { P(\mathrm{Data} \mid \mathrm{Parameter}) } \times \textcolor{#7570b3} { P(\mathrm{Parameter})} } {P(\mathrm{Data})} \]

  • \(\textcolor{#d95f02}{P(\mathrm{Parameter} \mid \mathrm{Data})}\)

    • What we want to estimate (posterior): When we got our data, what were the parameters behind the data (e.g., survival probability, coefficients of regressions)?

  • \(\textcolor{#1b9e77}{P(\mathrm{Data} \mid \mathrm{Parameter})}\)

    • When we know our parameters, what is the probability of getting our data? (i.e., likelihood)

  • \(\textcolor{#7570b3}{P(\mathrm{Parameter})}\)

    • What we assume about the parameter before we see the data (i.e., prior).

  • \(P(\mathrm{Data})\)

    • Does not depend on the parameters (i.e., a constant)

Prior and posterior

Seedlings again: prior × likelihood = posterior

  • Likelihood: 2 survivors out of 5, \(y \sim \mathcal{B}(5, p)\)
  • Prior: before the data, every \(p\) between 0 and 1 is equally plausible, \(p \sim \text{Beta}(1, 1)\)
  • Posterior: \(\propto p^2(1-p)^3 \times 1\)
  • The answer is a distribution, not a number.
  • We summarise it:
    • mean: 0.43
    • 90% interval: 0.15 to 0.73
    • \(P(p > 0.5 \mid \text{data})\) = 0.34
  • “Given the model and the data, there is a 90% probability that \(p\) is between 0.15 and 0.73.”
  • Beta(1,1) prior + 2 of 5 -> Beta(3, 4) posterior
  • contrast the interval statement with a confidence interval
  • this small table (mean / interval / probability statement) is the reporting pattern for the whole course

Prior vs. Data: MLE and Bayesian comparison (Coin Toss)

We compare two coins, A and B, with the same prior but different likelihood (due to data sizes) to illustrate how prior beliefs influence posterior estimates.

MLE

  • A: 2 head out of 3 tosses -> P(H) = 2/3 = 0.666
  • B: 60 heads out of 100 tosses -> P(H) = 60/100 = 0.6

Bayesian

  • \(\textcolor{#1b9e77}{L_A = {}_3C_2 p^2 (1-p)^1}\)

  • \(\textcolor{#1b9e77}{L_B = {}_{100}C_{60} p^{60} (1-p)^{40}}\)

  • \(\textcolor{#7570b3}{\mathrm{Prior} \propto p^{50} (1-p)^{50}}\)

    • Beta(51, 51): we believe coins are fair

Bayesian Update with Prior (Coin Toss)

Posterior \(\propto\) Likelihood \(\times\) Prior

Coin A: \(\textcolor{#d95f02}{Post_A}\propto\textcolor{#1b9e77}{p^2 (1-p)^1} \times\textcolor{#7570b3}{p^{50} (1-p)^{50}}\)

Peak of the posterior: \(p = 52/103 \approx 0.505\)

  • \(Post_A\): With only 3 coin tosses, the likelihood is weak, so the posterior stays close to the prior.

Coin B: \(\textcolor{#d95f02}{Post_B} \propto \textcolor{#1b9e77}{p^{60} (1-p)^{40}} \times\textcolor{#7570b3}{p^{50} (1-p)^{50}}\)

Peak of the posterior: \(p = 110/200 = 0.55\)

  • \(Post_B\): With 100 coin tosses, the likelihood dominates, so the posterior shifts more towards the data.
  • The same prior can have a strong or weak influence depending on how much data we have.
  • We usually have some sense of scale for our parameters, and we are allowed to use that information.

Four things that are easy to mix up

What it is Coin A (2 of 3, prior Beta(51, 51))
MLE the \(p\) that maximises the likelihood 0.667
MAP the \(p\) that maximises the posterior (its peak) 0.505
Posterior mean the average of the posterior 0.505
Posterior distribution every value of \(p\) with its plausibility Beta(53, 52)
  • MLE and MAP are single numbers. They say nothing about uncertainty.
  • With a flat prior, MAP = MLE. The posterior is still a distribution.
  • In this course we work with the whole posterior and summarise it with a mean (or median) and an interval.

Which prior? Simulate from it

  • Prior predictive check: draw \(p\) from the prior, simulate data, and ask “could data like these happen?”
  • A prior is a statement about plausible data, so judge it on the scale of the data.
  • In ecology we mostly use weakly informative priors: they rule out the impossible, and let the data speak.
  • informative prior here: earlier censuses suggest about 30% of seedlings survive
  • more on priors for regression coefficients on Day 2

From formulas to samples

Why do we need samples?

Goal: describe the posterior distribution of the parameters given the data.

  • For the seedling model we have a formula for the posterior, Beta(3, 4).
  • For almost every model we actually care about (regressions, hierarchical models), no formula exists.
  • Solution: draw many random samples from the posterior and summarise the samples.
  • MCMC (Markov Chain Monte Carlo) is a family of algorithms that produce such samples using only likelihood × prior.

MCMC: a simplified Metropolis-Hastings (MH) algorithm

  • Start with some values of p (e.g., 0.2 and 0.8).
  • Calculate the posterior of those values.
  • Repeat the following steps N times:
    • Propose a new value of \(p_{\text{new}}\) (e.g., \(p \pm 0.01\))
    • Calculate the posterior at \(p_{\text{new}}\).
    • If \(\text{Post}(p_{\text{new}}) \geq \text{Post}(p_t), \text{ then } p_{t+1} = p_{\text{new}}\).
    • Else, accept \(p_{\text{new}}\) with probability \(\frac{\text{Post}(p_{\text{new}})}{\text{Post}(p_t)}\).
  • After the first steps (grey: warmup), the chain visits each value of \(p\) in proportion to its posterior probability.
  • example: coin B, posterior proportional to p^110 (1-p)^90
  • two chains from different starting points end up in the same place: this idea returns on Day 2 as R-hat

Stan: A modern language/software for Bayesian modeling

  • 🧑🏻‍💻 Bayesian Modeling

    • Stan uses the No-U-Turn sampler (NUTS), a variant of Hamiltonian Monte Carlo (HMC). It uses the slope of the posterior to make long, efficient moves, so it works for models with many parameters.

  • ⚙️ Flexible and Scalable

    • You can use Stan for many types of models, from simple regressions to multi-level models including time-series, spatial, SEM, and more.

  • 💻 Multiplatform

    • Stan works with R, Python, Julia, and more. In this course we call Stan from R with cmdstanr.
  • we do not need the mechanics of HMC to use Stan well; optional slides are in the appendix
  • what we do need: check that the sampler worked (Day 2)

A Stan model = data + parameters + model

data {
  int<lower=0> N;             // number of seedlings
  int<lower=0, upper=N> y;    // number of survivors
  real<lower=0> a;            // prior: p ~ Beta(a, b)
  real<lower=0> b;
}

parameters {
  real<lower=0, upper=1> p;   // survival probability
}

model {
  // prior
  p ~ beta(a, b);
  // likelihood
  y ~ binomial(N, p);
}
  • data: what we observed, and the settings of the prior
    • \(N = 5\), \(y = 2\), \(a = 1\), \(b = 1\)
  • parameters: what we want to learn
    • \(p\)
  • model: prior and likelihood
    • \(p \sim \text{Beta}(a, b)\)
    • \(y \sim \mathcal{B}(N, p)\)

Stan returns draws from the posterior of every parameter.

We pass the prior settings as data, so you can change the prior from R without touching the Stan file.

The output is a table of draws

fit <- fit_or_load(
  "day1_seedling",
  "stan/binomial.stan",
  data = list(N = 5, y = 2, a = 1, b = 1)
)
fit$draws
.chain .iteration p
1 1 0.616
1 2 0.607
1 3 0.607
1 4 0.246

… 4000 rows

  • Posterior mean: mean(draws$p) = 0.43
  • 90% interval: quantile(draws$p, c(0.05, 0.95)) = 0.15, 0.72
  • \(P(p > 0.5)\): mean(draws$p > 0.5) = 0.34
  • Anything you can compute from \(p\), you compute for every draw.
  • fit_or_load() = cmdstan_model() + $sample(), with a fallback to stored results if sampling fails
  • the summary numbers differ slightly from the exact ones: Monte Carlo error

Summary of Day 1

  • Likelihood: how probable are the data for given parameter values.
  • Bayes’ theorem turns this around: posterior \(\propto\) likelihood \(\times\) prior.
  • The posterior is a distribution. We report means, intervals, and probabilities, not just the peak.
  • The prior matters when data are few, and fades as data accumulate.
  • When there is no formula, MCMC gives draws from the posterior. Everything we want is computed from the draws.

Appendix: optional material

MCMC: Hamiltonian Monte Carlo (HMC)

  • \(H(\theta, r) = U(\theta) + r^2/2\) (Hamiltonian: potential energy + kinetic energy = constant)

    • \(U(\theta) = -\text{log}\; p(\theta \mid \text{data})\)

  • Instead of sampling from \(p(\theta \mid \text{data})\), HMC samples from a joint distribution over both \(\theta\) and \(r\).

    • \(p(\theta \mid \text{data}) \propto \int \text{exp}(-H(\theta, r))dr\)

  • It’s equivalent to sampling from \(p(\theta \mid \text{data}) \propto \text{exp}(-U(\theta))\).

  • HMC explores very different \(\theta\) along the same trajectory (i.e. leapfrog path), which is much more efficient than random sampling.

MCMC: Hamiltonian Monte Carlo (HMC)

  • Within each iteration, HMC simulates a trajectory using leapfrog steps.

    • No-U-Turn Sampler (NUTS) dynamically determines the number of leapfrog steps; we only need to set the maximum (e.g., max_treedepth in Stan).

  • The Hamiltonian stays the same, but momentum \(r\) is resampled each iteration.

  • Only the final parameter \(\theta\) of each trajectory is kept as a posterior sample.

The code behind these animations: docs/hmc.qmd, R/hmc.R

Interfaces to Stan (for R users)

  • Stan: The actual modeling and inference engine, written in C++.

  • CmdStan: Command line interface (you write Stan code and run it via terminal).

  • rstan, cmdstanr: R interface to Stan/Cmdstan (you write Stan code and run it within R).

  • brms, rstanarm: Higher-level R packages that generate and run Stan models for you (you write an R formula, without writing Stan code).

  • In this course, we use cmdstanr with models that are already written. brms versions of the same models are shown as optional material on Day 2 and Day 3.
