# AFEC 2026：授業の再構成案（判断用）

2026-10-15

本書は講師の判断用の提案。採用前の案であり、現在のスライド・演習・学習目標を一括して変更するものではない。

## 1. 戻したい授業の軸

対象は、統計を専門にしていないEcologist。
授業の目的は「なぜベイズ推定が役に立つか」「なぜ階層モデルを使うか」を、生態学の問いと図を通して理解し、自分の研究で使う入口を得ることとする。

元の `main.qmd` の目標にはStan・Rの利用も含まれるが、講師ノートには「coding exercises are not the focus」「idea of Bayesian in ecology」とある。この位置づけを中心に戻す。

難しい数式をすべて消すのではなく、説明の順序をそろえる。

**身近な例・生態学の問い → まず予想する → 図を見る → 必要な数式で説明する → 生態学的に解釈する**

紹介する内容のすべてを、その場で計算・実装できることまでは求めない。
Stanのコードはモデルを具体化するために見せるが、全員が独力で書けることを修了条件にしない。

## 2. 前提と全体像

以下は未確認事項を含む、設計上の仮定。

- 3日間、各90分、受講者約30名。
- Rでコードを実行して図を見る程度の経験を想定する。tidyverseやGLMの習熟は必須にしない。
- ただし、全員日中に別の授業を受けてて、少なくともGLMの練習はしてるはず。
- ベイズ推定の経験は前提にしない。対数・確率・回帰も必要なところで短く説明する。
- 授業・受講者用教材は英語。講師用の本案は日本語。
- 相談はペアで行えるようにし、講師1名でも進められる構成を想定する。
- 必須の宿題は設けない案。発展資料は授業後にも参照できるようにする。
- ブラウザ環境を標準とし、事前確認済みのローカル利用も可能とする案。環境の最終決定は別途行う。

| 日 | 中心となる問い | 終了時にできてほしいこと | 受講者の演習 |
|---|---|---|---|
| Day 1 | データを見たら、考えはどう変わる？ | 事前・尤度・事後の役割と、データ量による変化を図と言葉で説明する | 短い図の比較を1回 |
| Day 2 | 生態学のデータをベイズで解析すると、何が分かる？ | 一つの回帰モデルの結果・予測を読み、データとの不一致を指摘する | 完成済みコードで結果を読む演習を1回 |
| Day 3 | データの少ない種や母樹を、どう扱える？ | partial poolingの意味と、研究で使う理由を説明する | 母樹の推定を比較する演習を1回 |

演習は減らすが、講義中の参加機会は残す。結果を見せる前の予想、隣の人への説明、全体への短い問いかけを入れる。

## 3. Day 1：ベイズの考え方に慣れる

### 説明の流れ

1. **生態学の入口**：苗木の生存率を知りたい。5個体のうち2個体が生き残ったとき、何が言えて、何がまだ分からないか。NDDや種間差は授業の行き先として短く見せる。
2. **尤度**：元のNormalの図で「あるパラメータなら、このデータはどの程度もっともらしいか」を見る。データを固定してパラメータを動かす。苗木に戻り、2/5という推定値だけでは不確実性が分からないことにつなぐ。
3. **順問題・逆問題**：条件付き確率、`fip_1`〜`fip_6`、PCRの例を使う。分かっている条件から結果を予想することと、結果から未知の条件を考えることを区別する。
4. **Bayesの定理**：「事後 ∝ 尤度 × 事前」を、それまでの例に対応づける。式の導出や記号の暗記は求めない。
5. **コイントスと苗木**：同じ事前分布でも、データ量によって事後の変化が違うことを見せる。コイントスの頭数と苗木の生存数は同じ二項モデルだと明示する。
6. **短い演習**：苗木の図を比較し、変化を言葉で説明する。
7. **Stanへの入口**：同じ苗木モデルのコードと保存済み結果を講師が見せる。「この考え方を計算してくれる道具」として紹介し、翌日の解析につなぐ。

### 90分の配分案

| 時間 | 内容 |
|---|---|
| 0–8分 | 接続確認、授業の行き先、苗木の問い |
| 8–23分 | 尤度の図、苗木の推定と不確実性 |
| 23–43分 | 条件付き確率、順問題・逆問題、PCR、Bayesの定理 |
| 43–58分 | 事前・事後、コイントス比較、苗木への対応づけ |
| 58–70分 | 図を比べる演習：8分の相談・操作＋4分の解説 |
| 70–80分 | Stanと事後サンプルの講師デモ |
| 80–85分 | 今日の考え方を受講者の言葉で振り返る |
| 85–90分 | 質問・遅延の余裕 |

時間は設計上の見積もり。順問題・逆問題の連続画像は説明を段階的に見せるためのもので、各画像を独立した新概念として長く扱わない。

### 演習案：データや事前を変えると、図はどう変わる？

- **目的**：事前分布とデータの役割を、自分の言葉で説明する。
- **スターター**：準備済み環境で以下の完成済みコードを配る。入力欄の穴埋めや図の作成コードの記述は求めない。

```r
plot_update(2, 5, 1, 1)
plot_update(40, 100, 1, 1)
plot_update(2, 5, 8, 2)
```

- **問い1**：最初の2枚では、事前分布と観測比率0.4を固定し、データ数だけを変える。どちらの事後分布が狭くなると予想するか。
- **問い2**：1枚目と3枚目では、データを2/5に固定して事前分布を変える。事後分布はどちらへ動くか。
- **提出する答え**：図から分かったことを一文ずつ。コードが動いたことだけを完了条件にしない。
- **期待する観察**：データが多いと推定が絞られる。少ないデータでは、強い事前分布が事後を大きく動かす。
- **解説の要点**：事前分布にも生態学的な理由が必要。「生存率が高い」という事前が、その生息環境で妥当かを尋ねる。

**本文に残す**：Normalの直感的な図、苗木、条件付き確率、`fip`、PCR、コイントス、事後分布の図。

**補足へ移す候補**：MLEの微分、Beta更新式の計算練習、MLE・MAP・事後平均の一覧表、Stan各ブロックの細かい読み解き、事後サンプルからの確率計算、新しい50個体の事後予測、MH/HMCの仕組み。

コイントスの事後ピークは図・結果として示してよいが、MAPの計算は講師ノートで扱う。Beta(51,51)は意図的に強い事前分布であり、推奨設定として提示しない。

**遅れた場合**：Stanデモを短縮し、演習の解説と最後の質問時間を確保する。MCMCの説明を追加して埋めない。

## 4. Day 2：一つの生態学的解析を読めるようにする

### 説明の流れ

1. **問いと散布図**：「太い木はどれくらい高いか？」を予想する。
2. **モデル**：一本の関係と、その周囲にばらつく木を図で表す。対数変換は既存のアロメトリーの例に沿って意味を説明するが、変換後の係数解釈を一度にすべて要求しない。
3. **推定結果**：一本の確定した線ではなく、もっともらしい線の幅として結果を読む。
4. **予測**：ある太さの木はどれくらい高いか。平均的な高さを知る不確実性と、個々の木のばらつきを図で区別する。
5. **短い演習**：完成済みの結果図から、生態学的な答えを述べる。
6. **モデルチェック**：モデルから作ったデータと観測を比べる。「図のどこが合っていないか？」を話す。
7. **計算の確認**：計算がうまくいかなかった例を短く見せる。警告がある結果をそのまま解釈しないことを伝える。

### 90分の配分案

| 時間 | 内容 |
|---|---|
| 0–10分 | Day 1の振り返り、木の高さの問いと予想 |
| 10–25分 | 散布図から回帰モデルへ |
| 25–40分 | 推定された関係と予測の図を読む |
| 40–55分 | 結果を読む演習：10分の相談・操作＋5分の解説 |
| 55–68分 | 観測とモデルからのデータを比較する |
| 68–78分 | 計算がうまくいかなかった例と注意点 |
| 78–85分 | 自分の研究なら何を予測・確認するか、全体で話す |
| 85–90分 | 質問・遅延の余裕 |

### 演習案：このモデルから、木について何が言える？

- **目的**：係数表の読み上げから、生態学的な結果の説明へつなぐ。
- **スターターの案**：既存の `day2/exercise.qmd` のデータ準備・保存済みfitの読み込み・描画を完成済みの短い実行ブロックにまとめる。受講者がStan用データリストや作図処理を書くことは求めない。これは今後作成する配布コードの仕様。
- **手順**：散布図から関係を予想する → 推定された線と幅を見る → DBHが40 cmと80 cmのときの予測を比較する → 新しい1個体の予測がどの程度ばらつくか読む。
- **答える問い**：「太さが違うと高さはどう違うか」「同じ太さの木なら、全個体が同じ高さになるか」。数値・範囲と一文の解釈を組み合わせる。
- **期待する観察**：平均的な関係があっても個体差は残る。関係の推定が精密でも、新しい1個体の高さを正確に当てられるとは限らない。
- **解説の要点**：関係を示す図と、モデルが観測を再現できるかの確認を両方見る。統計的な関連から因果関係を断定しない。

**本文に残す**：アロメトリーの問い、モデルの意味、結果と予測の図、簡単なモデルチェック、計算上の警告を見る必要性。

**補足へ移す候補**：ロジスティック回帰の独立した演習、logit・odds ratioの詳細、事前予測の実装課題、壊れたモデルの修正課題、診断指標の計算や閾値を覚える課題、brmsとのコード比較。

R-hat・ESSなどは、何を確認する道具かを短く紹介する。講師側では既存の複数診断とモデルチェックを継続して確認し、受講者向けの簡略化を検証の省略にはしない。

**遅れた場合**：診断の実演を短くして確認方法の資料を配る。中心の解析例、モデルチェック、演習の解説を残す。

## 5. Day 3：階層モデルを使う理由をつかむ

### 説明の流れ

1. **問い**：母樹ごとに苗木の数も生存率も違う。少数の苗木しかない母樹の0%・100%を、そのまま信じてよいか。
2. **両極端を見る**：すべて同じ生存率とする場合と、母樹ごとに完全に別々に推定する場合を比べる。
3. **partial poolingを見る**：母樹ごとの違いを認めながら、共通する情報も使うモデルとして説明する。
4. **短い演習**：どの母樹の推定が動くかを予想し、結果図と比べる。
5. **研究の例へ広げる**：種ごとのアロメトリー、wood density、冒頭のNDDへ戻る。母樹と種は別のグループであり、二項の生存モデルと連続値の回帰では観測モデルが違うが、グループ間の情報共有という構造が共通だと示す。
6. **自分の研究へ**：何をグループと考えるか、どんな違いを知りたいかを話す。

### 90分の配分案

| 時間 | 内容 |
|---|---|
| 0–10分 | 振り返り、母樹の問い |
| 10–25分 | 全体を同じとする推定／別々の推定を図で比較 |
| 25–40分 | partial poolingの意味と、推定が動く理由 |
| 40–55分 | 母樹の演習：10分の相談・操作＋5分の解説 |
| 55–70分 | 種ごとのアロメトリー・wood density・NDDへのつながり |
| 70–80分 | モデルの前提と注意点、自分の研究での使い方 |
| 80–85分 | 3日間の振り返り |
| 85–90分 | 質問・遅延の余裕 |

### 演習案：どの母樹の推定が、どちらへ動く？

- **目的**：情報共有によって推定が変わる意味を、母樹のデータに結びつける。
- **スターターの案**：既存の `day3/exercise.qmd` の三つの推定を比較する完成済み図と、保存済み結果からその図を表示するコードを配る。三つのモデルをそれぞれ実装する課題にはしない。これは今後作成する配布コードの仕様。
- **手順**：各母樹の苗木数と生存割合を見る → 動きそうな母樹を二つ選び理由を書く → 結果を表示する → 予想と違ったところを話す。
- **期待する観察**：データの少ない母樹の推定は共通する情報の影響を受けやすい。群間差が大きいとモデルが推定すれば、情報共有による動きは弱くなる。
- **解説の要点**：partial poolingは、すべての母樹で必ず誤差を減らす保証ではない。母樹間に共通性を仮定することが、生態学的に妥当かを考える。

**本文に残す**：元の母樹の例、三つの推定の比較、情報共有の意味、元の研究例への接続。

**補足へ移す候補**：varying interceptとvarying slopeを別々に実装する演習、階層標準偏差の計算課題、新しい母樹・種の予測課題、共分散・Cholesky・LKJ、non-centered化の詳細、ソフトウェア間比較。

**遅れた場合**：研究モデルの数式・コードの説明を短くする。母樹の図の比較と、生態学的な意味の説明を残す。

## 6. 既存教材をどう扱うか

| 内容 | 本案での扱い |
|---|---|
| `main.qmd` の身近な説明・図 | 説明の入口として優先的に使う |
| `fip_1`〜`fip_6`、PCR、コイントス | Day 1の本文に残す。別々の計算演習にはしない |
| 尤度のNormal例・苗木の例 | 残す。分布の違いを説明し、対数尤度・微分の詳細は補足へ |
| 既存の細かい必須課題 | 保存した上で、講師デモ・任意課題・補足へ振り分ける |
| 母樹・種間差・NDDの動機 | 授業の中心として残す。現場で何を知りたいかを先に話す |
| 論文由来の問いと教材データ | 実際の研究の紹介と、教材のシミュレーションを区別する |
| Stanモデル・データ・保存済みfit | 本案の採否によって統計モデルや解析結果を変更する必要はない |
| 解説・診断結果の詳細 | 講師用資料と発展資料に残し、理解のために必要な範囲を本文に出す |

## 7. 準備と実施の考え方

- 授業前に接続・図の表示まで確認する。授業中のインストールやコンパイルを必須にしない。
- コードを動かせない場合も、配布済みの図・表を使って同じ問いに答えられるようにする。
- 必須演習は保存済み結果か軽い計算を使う。新しく推定する実演は環境と時間の確認後に選ぶ。
- 時間配分は未計測。実機での実行確認と、説明を含めた通し練習で調整する。
- 発展内容は90分に追加しない。授業後の任意資料、または基本部分を終えた人向けとして扱う。

## 8. 講師に判断してほしい点

1. **到達点**：自力でモデルを書くことより、考え方・図の解釈・研究への接続を優先してよいか。
2. **Day 1**：`fip`・PCR・コイントスを残し、受講者が操作する演習を一つに絞るか。
3. **Day 2**：アロメトリーを中心の解析例にして、ロジスティック回帰は発展扱いにするか。生存モデルを主例にしたい場合は、二つを詰め込まず入れ替える。
4. **Day 3**：母樹で理解し、wood density・NDDは研究への接続として講師が見せる形でよいか。
5. **Stan**：完成済みモデルと結果を読むところまでを共通とし、編集・実装は希望者向けでよいか。

採用方針が決まってから、スライド、演習、講師用進行表、配布版をそろえて改訂する。
